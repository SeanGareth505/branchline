Overview

Branchline is a desktop Git client. It runs as a native app (Tauri) and talks to Git on your machine — your repos, credentials, and tokens stay local.

The main workflow is: open a repository, browse branches and history, review changes, commit, sync with remotes, and open pull requests. Settings covers appearance, Git defaults, notifications, and connections to GitHub, GitLab, Azure DevOps, and Jira.

Top navigation

  • Branchline — return to the repository picker or your open repo.
  • Repo — branches, commit graph, diff, and file tree.
  • PRs — pull requests for the current repository.
  • Jira — linked issues when Jira is connected (optional).
  • Release — GitHub releases, version bumps, tags, and release tracking.
  • Identity / Automation — visible in Advanced mode only.
  • Settings — preferences, connections, updates, and this guide.

Press ⌘K (Ctrl+K on Windows/Linux) anywhere to open the command palette — it can jump to views, run Git actions, and open settings sections.

Repositories

When no repo is open, or from Settings → Repos, you can open an existing folder, clone from a URL, or initialize a new repository.

  • Open — pick a local folder that already contains a .git directory.
  • Clone — download a remote repository into a folder on your machine.
  • Init — create a new empty Git repository in a folder.
  • Recent repos — quick access to repositories you opened before.
  • Repo tabs — keep several repositories open and switch between them.

The status bar at the bottom shows the current branch, sync state (ahead/behind), and the app version. Click the version to open About and updates.

Repo view

The Repo view is a three-part workspace you can resize by dragging the splitters.

  • Left panel — branches, remotes, tags, stash, worktrees, and more.
  • Center — the commit graph (revision grid).
  • Bottom — detail tabs for the current selection.

Bottom tabs

Commit
Message, author, and metadata for the selected commit.
Diff
Code changes for the selected commit or working tree.
Files
File tree of changes; stage and unstage from here.
Blame
Line-by-line authorship (Advanced mode).
History
Commits that touched the selected file (Advanced mode).
Reflog
Recent HEAD moves — checkouts, resets, amends (Advanced mode).
Console
Run raw Git commands against the repo (Advanced mode).

Simple mode (Settings → Appearance) hides Advanced-only tabs and top-level views like Identity and Automation so the UI stays focused on everyday Git work.

Branches & refs

The left refs panel groups local branches, remote-tracking branches, and tags. Branches with slashes in their name are shown in folders (for example feature/login).

Branch interactions

  • Single-click — select that branch's tip commit in the graph and open the Diff tab.
  • Double-click — check out the branch (switch your working tree to it).
  • Right-click — context menu for merge, rebase, delete, rename, upstream, and more.

Visual indicators

Blue left bar (solid)
The branch you currently have checked out.
Blue left bar (lighter)
This branch's tip is the commit selected in the graph — not that the branch row itself is selected. If two branches share the same commit, both show the bar.
Tree guides
Gray lines connecting folder groups — not selection marks.

Other ref sections

  • Remotes — configured remotes and fetch/push URLs.
  • Tags — named pointers to commits, often used for releases.
  • Stash — saved work-in-progress snapshots.
  • Worktrees — additional checkouts of the same repo in other folders.
  • Submodules — nested repositories referenced by the parent repo.
  • LFS — large files tracked by Git LFS.

Commit graph

The revision grid shows commit history as a graph with branch lanes. Click a commit to select it — the Commit and Diff tabs update to match.

  • Focus mode (Settings → Appearance) dims commits outside the current branch lineage so you can follow one line of history.
  • Compare — select one commit, then compare it to another to see a range diff.
  • Multi-select — hold modifier while clicking to select multiple commits (for example when cherry-picking a range).

Branch labels on the graph show where refs point. The graph scrolls to reveal a commit when you click a branch or use "Show in graph" from elsewhere in the app.

Commits & changes

Uncommitted work appears in the Files tab with a change count badge. Stage files, review diffs, then commit.

  • Commit dialog — open with the toolbar button or ⌘⇧C. Supports commit types, templates, sign-off, and amend.
  • Commit checks — optional pre-commit validation rules (Automation → Checks).
  • Conflict resolution — when a merge or rebase conflicts, a banner guides you through resolving files.
  • Operations in progress — merge, rebase, cherry-pick, and bisect show banners and next-step actions in the status bar.

Many Git operations are available from the command palette, branch context menus, or dedicated dialogs: cherry-pick, interactive rebase, stash, git clean, git flow, branch hygiene, and publish to GitHub.

Fetch, pull & push

Sync controls live in the repo toolbar and status bar. Branchline uses your system Git — SSH keys or credential helpers — for fetch, pull, and push.

  • Fetch — download new commits from remotes without changing your working tree (⌘⇧F).
  • Pull — fetch then merge or rebase (default chosen in Settings → Git).
  • Push — upload local commits. Unpublished branches can be pushed with upstream tracking set.
  • Sync preview — review incoming and outgoing commits before pulling or pushing.

The status bar shows ahead/behind counts relative to the upstream branch. Click the GitHub chip to switch HTTPS vs SSH or pick a GitHub CLI account for this repo.

GitHub OAuth or a PAT is optional when GitHub CLI is already logged in. Clone, fetch, pull, and push still go through system Git — SSH keys or the GitHub CLI credential helper.

Pull requests

The PRs view lists open, closed, and draft pull requests for the current repository when a GitHub account is added (GitHub CLI) or a GitHub / GitLab / Azure token is connected.

  • Create PR — open a pull request from your current branch, with optional templates.
  • Reviews and checks — see who approved, who requested changes, and whether CI is passing or blocked.
  • Copy — copy matching PRs as links, markdown, Slack, standup notes, checkout commands, or all open PRs for a repo.
  • Notifications — toast, desktop, and optional sounds when a PR needs your review, is ready to merge, or CI changes.

Add a GitHub account under Settings → Connections. Organization repos may still require SSO or a PAT if GitHub CLI cannot see the repo.

Release

The Release view can watch GitHub releases for any linked repository, including client projects that do not ship versions through Branchline.

  • Watch latest — load the newest GitHub release and follow installer builds when GitHub Actions is used. Opening the Release tab does this automatically for repos that ship through Branchline.
  • Version bump — increment semver in project files when a version source is configured.
  • Tag & push — create an annotated tag and push it to the remote.
  • Changelog — extract commit messages between tags or branches for release notes.
  • CI tracking — follow GitHub Actions workflow runs tied to the release.

Creating a release from Branchline needs a file with a semantic version (usually package.json). Workspace roots without a version can still browse GitHub releases. In a monorepo, pick an app to see that app’s deploy workflow and tags — each app can ship separately. Do not add release.config.json to a client repo unless you intend to ship from Branchline.

Connections

Settings → Connections links Branchline to external services.

GitHub
GitHub CLI accounts for fetch, push, and pull requests. Optional PAT or GitHub sign-in for orgs that need it.
GitLab / Azure
Personal access tokens for API features on those hosts.
Jira
Link issues, create branches from tickets, and show ticket keys parsed from branch names.
SSH
Generate or inspect SSH keys used by system Git for remotes.

First-run onboarding walks through identity, remotes, and optional SSH setup. You can reopen any step from Settings later.

Advanced

These areas appear when Simple mode is off (Settings → Appearance).

Identity

Manage Git author profiles — global vs per-repository identity, signing keys, and which profile applies when you commit.

Automation

One-click workflow sequences (fetch, pull, create branch, and more) with placeholders like {{ '{' }}date{{ '}' }} and {{ '{' }}ticket{{ '}' }}. Commit Checks define rules that run before a commit is allowed.

Inspect tools

Blame, per-file history, reflog, and the Git console give deeper visibility into repository state beyond everyday commit and diff review.
